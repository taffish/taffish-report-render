# Report Spec Manual

`taffish-report-render` compiles one report specification plus one result root
into a standalone TAFFISH HTML report.

The normal input is:

- `--spec report.toml` or `--spec report.manifest.json`;
- `--root OUTDIR`, the local result directory that contains report assets.

The spec describes report structure. The root directory contains the actual
data assets. Users should not write final HTML, JavaScript, CSS, or auxiliary
layout files.

## Top-Level Shape

A minimal TOML spec looks like this:

```toml
schema_version = "0.1"
template = "taffish-flow-report"
language_default = "en"

[project]
flow_name = "example-flow"
flow_version = "0.1.0-r1"
analysis_mode = "reference"
title.en = "Example report"
title.zh = "示例报告"
subtitle.en = "A standalone TAFFISH report generated from TOML."
subtitle.zh = "由 TOML 生成的 TAFFISH 单文件报告。"

[[sections]]
id = "overview"
kicker.en = "Overview"
kicker.zh = "总览"
title.en = "Project Overview"
title.zh = "项目总览"
text.en = "Start with the status cards and main outputs."
text.zh = "先查看状态卡和主要输出。"

[[sections.components]]
id = "summary_cards"
type = "dashboard_cards"
source = "03_results/tables/summary.tsv"
```

Required top-level fields:

- `schema_version`: currently `0.1`.
- `template`: currently `taffish-flow-report`.
- `project`: report metadata shown in the hero and provenance.
- `sections`: ordered report sections.

Optional but recommended top-level fields:

- `language_default`: `en` or `zh`.
- `languages`: explicit language list when the report needs more than the
  default.
- `provenance`: structured tool and source metadata.

## Project Metadata

`project` should contain stable machine-readable values and user-facing labels:

- `flow_name`: app or flow name, for example `rnaseq-standard-flow` or
  `taffish-report-render`.
- `flow_version`: TAFFISH package version such as `0.3.0-r1`.
- `analysis_mode`: short mode label such as `reference`, `denovo`, `quality`,
  or `component-regression`.
- `title`: localized report title.
- `subtitle`: localized report subtitle.

The renderer displays hero metadata as separated label/value fields. Do not put
labels inside the value itself.

## Sections

Each section needs a stable unique `id`. Section IDs are used for the left
navigation and URL anchors.

Reserved IDs are generated by the renderer and must not be used manually:

- `report-guide`
- `deliverables`
- `provenance`

Recommended section fields:

- `id`
- `kicker.en` / `kicker.zh`
- `title.en` / `title.zh`
- `text.en` / `text.zh`
- `components`

Section order in TOML is the order in the report. Component order inside a
section is also preserved.

## Components

Every component must have:

- `id`: unique within the report;
- `type`: one registered fixed component type.

The renderer rejects unknown component types. Component-specific fields are
documented in [components.en.md](components.en.md).

Layout fields are typed renderer inputs, not CSS escape hatches. For example,
`plot_card layout = "media"` accepts a numeric `media_image_ratio` only in the
validated `0.25` to `0.70` range and predefined position/alignment/gap enums.
Unknown values fail lint; report specs cannot inject arbitrary CSS strings.

Example:

```toml
[[sections.components]]
id = "volcano"
type = "interactive_plot"
kind = "volcano"
source = "03_results/tables/de.results.tsv"
title.en = "Interactive volcano plot"
title.zh = "交互火山图"
```

## Paths and Root

All data paths are resolved relative to `--root`. For example:

```toml
source = "03_results/tables/de.results.tsv"
image = "03_results/plots/de.volcano_plot.png"
path = "03_results/tree/final_tree.nwk"
```

The renderer rejects:

- absolute paths;
- `..` traversal outside `--root`;
- missing files;
- unsupported file kinds for a component.

This keeps reports reproducible and prevents accidental embedding of
maintainer-local files.

## I18n

Visible explanatory text should usually provide both English and Chinese:

```toml
title.en = "Differential expression"
title.zh = "差异表达"
text.en = "Genes with condition-associated changes."
text.zh = "与条件差异相关的基因。"
```

Scientific values are not translated automatically. Gene IDs, p-values, file
paths, tool names, and table data remain as produced by the analysis.

For tables, language-paired columns such as `note_en` / `note_zh` or
`criterion_en` / `criterion_zh` are rendered according to the active report
language when the component supports language folding.

## Collections

Collection components are compile-time helpers. They read an index TSV and
expand into regular components during `migrate` or `render`.

Available collection helpers:

- `plot_collection`
- `table_collection`
- `code_file_collection`
- `native_subreport_collection`

The expanded canonical manifest is written to `report.normalized.json` so the
final report remains auditable.

## Output Sidecars

Rendering writes the standalone HTML plus audit/debug sidecars:

- `report.spec.toml`: copied input spec;
- `report.full.toml`: fully generated spec when a test or flow creates one;
- `report.normalized.json`: canonical expanded manifest;
- `report.manifest.json`: rendered manifest;
- `report_files.tsv`: embedded and linked asset index;
- `embedded_html_reports.tsv`: native HTML subreport index;
- `report_template_version.txt`: renderer template version.

Only the HTML is needed for reading. Sidecars help audits and debugging.

## Validation Workflow

Recommended flow-side validation:

```sh
taf-taffish-report-render lint --spec report.toml --root OUTDIR
taf-taffish-report-render explain --spec report.toml --root OUTDIR
taf-taffish-report-render render \
  --spec report.toml \
  --root OUTDIR \
  --out OUTDIR/04_reports/taffish_report.html \
  --force \
  --validate
taf-taffish-report-render inspect-html OUTDIR/04_reports/taffish_report.html --validate
```

For a full component reference, read [components.en.md](components.en.md).
